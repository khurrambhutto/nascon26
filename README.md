## Run the backend

Set the organizer-provided `DAY1_SALT` in your shell; never commit the real value.

```sh
export DAY1_SALT='your-team-slip-value'
docker compose up -d --build
curl http://localhost:8080/health
```

PowerShell: `$env:DAY1_SALT = 'your-team-slip-value'`, then run the same Docker command.
The API listens on **8080**. OpenAPI documentation: `http://localhost:8080/docs`.
Postgres, Redis Streams, MinIO and the outbox worker are self-hosted. Database schema and demo content initialize automatically.
`POST /audit/v1/reset` replaces all competition state and recreates baseline/demo data.
If `JWT_SECRET` is omitted, the JWT signing key is derived from the private team salt using a separate HMAC context. Passwords use individually salted PBKDF2 hashes.
The Docker build uses a complete Python 3.12/Linux x86_64 wheel lock with SHA-256 checksums, avoiding package-version resolution during grading. A cold build requires internet only for these public PyPI artifacts and the pinned Docker images.

The booklet's unavailable MinIO image is replaced with `bitnamilegacy/minio:2024.9.22`; notify the organizers of this compatibility substitution.

## Local receipt inbox

Open **http://localhost:8080/local-mail** and sign in with an ArenaOne demo account below. Successful app purchases with a receipt address are captured by the internal `local-mail` SMTP service. Customers see their own receipts; platform admins see all receipts. Open a message to download its PDF.

The default Compose configuration needs no Google account, app password or internet mail provider. Captured messages remain in the local Postgres volume and are not delivered to the recipient's external email account. The app receipt screen includes **Open local inbox**. The internal SMTP port is not published to the host.

## Backend tests

```sh
./run_tests.sh
```

The script uses a local Linux virtualenv if available, otherwise the built API container; the grader needs no host Python packages. Build the stack first.
For local Python development: `cd backend`, `uv venv --python 3.12`, then `uv pip install -r requirements.txt -c constraints.txt`.
On Windows use `backend/.venv/Scripts/python.exe -m pytest backend/tests -q` from the repository root.
Unit tests use an isolated SQLite database; deployment uses PostgreSQL with a database-backed lock for atomic domain mutations.
Coverage figures in `COVERAGE.json` are generated by `tests/write_coverage.py`, not manually estimated.

`python tests/smoke_backend.py http://127.0.0.1:8080` exercises the actual PostgreSQL-backed stack, including a 20-buyer race. **It resets server data**; run it only on a disposable/demo stack. An optional second URL splits the burst across two API processes.
`python tests/smoke_stream.py http://127.0.0.1:8080` verifies live SSE score updates.

## Additional operations API

The required mobile and audit contract is in `PLAN.md`; all actions use the same underlying domain services.

| Endpoint | Purpose / permission |
|---|---|
| `GET /api/v1/sports` and `/sports/{id}` | Read scoring rules to generate sport-specific controls |
| `PUT /api/v1/venues/{id}` | Organizer/admin venue availability configuration |
| `POST /api/v1/matches/{id}/reschedule` | Owned-league scheduling with venue, team, player and rest conflicts |
| `POST /api/v1/matches/{id}/status` | Owned-league status transitions and downstream postponement |
| `PATCH /api/v1/leagues/{id}/configuration` | Season, division, format, promotion/relegation and minimum-rest configuration |
| `PATCH /api/v1/tenants/{id}/branding` | Platform-admin white-label name, color and logo |
| `GET /api/v1/orders` and `/orders/{id}` | Customer/own-club manager order history |
| `PATCH /api/v1/orders/{id}/status` | Club-manager/admin fulfilment, cancellation and mock refund |

Order transitions require a client-generated `request_id`; replay never repeats a refund or stock return.
Fixture generation remains pure computation as required by the audit contract; callers register its resulting fixtures through `/audit/v1/leagues`.

## Architecture

Domain modules are separated into scoring, standings, fixtures, roster, store, authorization and offline synchronization.
PostgreSQL persists domain records in JSON with a global transaction mutex. This deliberately simple design serializes mutations across API processes, prioritizing correctness at competition scale over independent parallel writes.
An order and its durable outbox event commit together. The worker publishes order events to Redis Streams and archives receipts in MinIO; receipt PDFs are returned synchronously by checkout.
Match SSE streams detect committed changes every second and send `event: update`; the mobile contract also permits a three-second polling fallback.

For deployment outside the competition, replace demo credentials/secrets and restrict the audit/reset interface to a trusted evaluation network.
